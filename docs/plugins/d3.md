# D3 diagrams plugin

`uml-mcp-plugin-d3` adds three diagram types that render **locally**, with no Kroki call. Each
one produces a standalone **HTML** page you can zoom, pan and rearrange, or a static **SVG**
for a chat preview.

The look is that of a clean engineering diagram: a dotted canvas, compact monospace cards with a
tinted fill, a coloured outline and a small icon, straight arrows, boundaries titled on their dashed
border, and a legend that counts what is drawn. There is a light and a dark theme, and the page
switches between them in place.

| `diagram_type` | What it draws | Flows |
| --- | --- | --- |
| `d3_force` | A force-directed graph: nodes pulled together by links, coloured by group | n/a |
| `d3_architecture` | Boxes in nested groups with cloud-service icons, input and output ports, and arrows routed around the boxes | left to right |
| `d3_topology` | The same engine for deployments and networks: zones, tiers, devices | top to bottom |

It also adds one read-only tool, `d3_catalog`, that lists the providers, service names and icon
kinds a diagram can use.

!!! tip "Where this fits"

    Need the vendors' **official** icons? Use the PlantUML icon libraries instead, see
    [Cloud architecture diagrams](../diagrams/cloud-architecture.md). Use this plugin when you want
    an **interactive** diagram, nested groups, named ports, or a page that works offline.

## Install and enable

Vercel includes and enables this plugin by default through `uml-mcp.vercel.yaml`.
Other installations can enable it with `uml-mcp plugins enable d3`.

The plugin source lives in the repository under `examples/plugins/uml-mcp-plugin-d3`.

```bash
uv pip install -e examples/plugins/uml-mcp-plugin-d3   # next to uml-mcp
uml-mcp plugins enable d3                              # one name enables the tool and the renderer
```

Restart the server. `uml-mcp plugins list` shows `d3` as enabled, and the three types appear in
`list_diagram_types`, `uml://types`, `uml://examples` and `uml://templates`. See
[Plugins](index.md) for how loading and the allow-list work.

## Use it from an MCP client

```json
{
  "name": "generate_uml",
  "arguments": {
    "diagram_type": "d3_architecture",
    "code": "{\"nodes\": [{\"id\": \"web\", \"kind\": \"server\"}, {\"id\": \"db\", \"kind\": \"database\"}], \"links\": [{\"from\": \"web\", \"to\": \"db\"}]}",
    "output_format": "svg"
  }
}
```

| Goal | Call | What comes back |
| --- | --- | --- |
| Show the diagram in the chat | `output_format: "svg"` | An image block the client can display, plus the SVG as `content_base64` |
| Get the interactive page | `output_format: "html"`, `output_dir: "<folder>"` | The page is written to the folder; the result has `local_path` and the summary says `Saved to: ...` |
| Get a small page as bytes | `output_format: "html"` without `output_dir` | `content_base64` only when it fits the 48,000-character initial-result budget; otherwise an explanation. Use file export for full offline pages. |
| Check a source without rendering | `validate_uml` | Every problem at once, for example `links[0].to 'zzz': no such node` |
| See what a diagram can use | `d3_catalog` (optionally `provider: "aws"`) | Providers, `provider:service` names and icon kinds |

!!! note "Writing files"

    `output_dir` follows the server's normal rules: it must be inside `MCP_OUTPUT_ROOT` (or
    `MCP_ALLOW_ARBITRARY_OUTPUT_DIR` must be on), and hosted or memory-only servers never write
    files. Hosted HTML results are subject to the initial-result size budget; use SVG or PNG for their chat preview.

The source is JSON. A markdown fence around it (` ```json `) is accepted, since models often add
one. Unknown fields are rejected, so a typo such as `lable` is reported instead of ignored.

## Force graph (`d3_force`)

```json title="d3_force"
{
  "title": "Service dependencies",
  "directed": true,
  "nodes": [
    {"id": "web", "label": "Web app", "group": "frontend", "size": 1.4},
    {"id": "gateway", "label": "API gateway", "group": "edge", "size": 1.6},
    {"id": "orders", "label": "Orders", "group": "backend", "size": 1.3},
    {"id": "db", "label": "Postgres", "group": "data", "note": "primary + replica"}
  ],
  "links": [
    {"source": "web", "target": "gateway"},
    {"source": "gateway", "target": "orders", "label": "REST"},
    {"source": "orders", "target": "db"}
  ]
}
```

| Field | Where | Meaning |
| --- | --- | --- |
| `title` | top | Heading of the page and the SVG |
| `theme` | top | `light` (default), `dark`, or `auto` to follow the system setting |
| `directed` | top | Draw arrowheads on the links (default `false`) |
| `charge` | top | Repulsion between nodes, -5 to -2000 (default -220) |
| `distance` | top | Preferred link length, 10 to 400 (default 70) |
| `id` | node | 1 to 64 characters of `A-Z a-z 0-9 _ - .`, unique |
| `label` | node | Text under the circle (default: the `id`) |
| `group` | node | Nodes with the same group share a colour; a legend is drawn |
| `size` | node | Circle size, 0.5 to 4 (default 1) |
| `note` | node | Shown in the tooltip |
| `source`, `target` | link | Node ids; a node cannot link to itself |
| `label` | link | Text on the link |
| `value` | link | Link thickness, 0.1 to 10 (default 1) |

The SVG and the page start from the same deterministic layout, so the page opens near its settled
shape and does not jitter. Graphs of more than 150 nodes skip the quadratic layout step and start
from a ring grouped by `group`; the page then runs the live simulation as usual.

### Fields

| Field | Where | Meaning |
| --- | --- | --- |
| `title` | top | Heading of the page and the SVG |
| `theme` | top | `light` (default), `dark`, or `auto` to follow the system setting |
| `provider` | top | The default provider of a node's `service`: `aws`, `azure`, `gcp`, `kubernetes`, `onprem`, `tech` or `generic` (default) |
| `direction` | top | `LR` or `TB`; default `LR` for `d3_architecture`, `TB` for `d3_topology` |
| `id` | group, node | 1 to 64 characters of `A-Z a-z 0-9 _ - .`, unique among groups, and among nodes |
| `label` | group, node, link | Display text. A node with a `service` but no `label` shows the service name |
| `type` | group | `boundary` (default), `system`, `env`, `region`, `zone`, `vpc`, `subnet`, `cluster`, `account`: sets the border style |
| `parent` | group | Nest a group inside another. A group may not be its own ancestor, and every group must contain a node |
| `service` | node | `provider:service` (for example `aws:s3`), or the bare service name to use the diagram's `provider` |
| `kind` | node | Picks the icon shape directly (see [icon kinds](#icon-kinds)); wins over the icon of `service` |
| `category` | node | Overrides the category (colour) a node gets from its kind: see [categories](#categories) |
| `logo` | node | The node's own logo, as a data URI: see [logos](#logos) |
| `group` | node | The group the box sits in |
| `inputs`, `outputs` | node | Named ports, up to 12 each, drawn on the left and right edge |
| `note` | node | Shown in the tooltip |
| `from`, `to` | link | A node id, or `id:port` to attach to a named port |
| `style` | link | `solid` (default, slate), `dashed` (violet, for asynchronous links) or `primary` (green and heavier, for the main flow) |

A link that names a port that the node does not declare is an error, as is an unknown group,
kind, provider or node. `validate_uml` returns all of them at once.

## Working with the page

| Action | How |
| --- | --- |
| Zoom | Mouse wheel, the **+** and **−** buttons, or the `+` and `-` keys |
| Pan | Drag the background |
| Fit everything | **Fit** or the `0` key |
| Light or dark | **Theme** |
| Animate the arrows | **Flow** (architecture and topology). It stops when the system asks for reduced motion |
| Move a box | Drag it. The box snaps to a 10 px grid and the arrows around it are routed again as it moves |
| Pin a node (force graph) | Drag it; it keeps its place. Double-click to release it |
| Pause the simulation (force graph) | **Pause**, then **Resume** |
| Highlight connections | Hover a box or node; everything unrelated fades and a tooltip shows its `note` |
| Undo all your moves | **Reset** |
| Save the picture | **Export**, then **Save SVG** or **Save PNG** |
| Save the page | **Export**, then **Save HTML** |

### Saving what you arranged

**Save HTML** downloads a standalone page holding the diagram **as it is now**, in the theme you chose: the boxes where you
dragged them, the arrows routed around them, and any pinned nodes. Open it later and it continues
from there, with the same behaviour. **Save SVG** gives the picture alone, with its stylesheet inside, and **Save PNG** the same picture
as an image at twice the size. If you dragged a box past the
original edge, both exports grow to include it, and the zoom you had is not carried over.

The page needs the network only to load D3. Set [`d3_source: inline`](#settings) and the page,
and every export of it, works offline.

## How arrows avoid boxes

Arrows are drawn as right-angled lines and are routed with **A\*** on a 10 px grid:

- Every box is an obstacle, with an 8 px margin around it.
- A path pays for its length, for each turn (three steps, so an arrow bends only when it must),
  for running along an arrow routed before it (four steps) and for crossing one (a step and a half).
  Arrows are routed in the order they are declared.
- An arrow leaves and enters a box through a short straight stub, so it never grazes a box edge.
- Boxes stay at least **40 px apart**, in the layout and while you drag. That leaves a corridor
  an arrow can use. A box dropped too close to another goes to the **nearest free place** on the
  grid instead of overlapping it.

The same algorithm runs in Python (for the SVG and the starting layout) and in JavaScript (while
you drag). The tests check that both return identical paths.

### Straight lines

Most arrows come out as a single straight line, because the layout aims for it before the router
starts:

- Boxes in a lane line up on the row their arrows use (a port's row, otherwise the middle of the
  card), not on their tops. Boxes of different heights still meet head-on.
- Every arrow end without a port slides along its box side to the spot, on the grid and clear
  of the other arrows, that is nearest the other end. The spots are chosen together, in order,
  so the arrows do not cross and the total slide is the smallest possible.
- A box is placed in the lane of the boxes it is linked to, so a chain stays on one row.

In the two shipped architecture and topology examples, 10 of the 14 arrows are a single straight
line (4 were before the layout and routing were tuned for it).

### Connection labels

A label sits on the middle of the **longest straight run** of its arrow that is long enough for
it, never on the arrowhead's run unless nothing else fits, and a halo in the canvas colour breaks
the line behind the text. The placement is recomputed while you drag.

Boxes are laid out in layers by longest path (a cycle is allowed; one of its links is simply
ignored for layering). Boxes whose layers do not overlap share a row, so a chain such as
`users → cdn → api → orders` stays in one straight line. Groups are drawn as the box around their
members, so two groups never overlap, and a group resizes as you move its members.

## Settings

In `uml-mcp.yaml`:

```yaml
plugins:
  enabled: [d3]
  settings:
    d3: {d3_source: inline, max_nodes: 200}
```

| Key | Default | Meaning |
| --- | --- | --- |
| `d3_source` | `cdn` | `cdn` loads D3 7.9.0 from jsDelivr, pinned and checked with a Subresource Integrity hash. `inline` embeds the vendored copy: the page works offline and is about 280 KB larger |
| `max_nodes` | `400` | Refuse diagrams with more nodes, from 1 to the hard cap of 400 |

Enabling the plugin adds the `d3_catalog` tool and the three diagram types to what a client
loads when it connects, about 250 tokens in `uml-mcp lint`.

A bad value makes the plugin show as failed on the console's **Tools & plugins** page; the
server still starts.

## Limits and safety

| Limit | Value |
| --- | --- |
| Nodes | 400 (`max_nodes` lowers it) |
| Links | 1500 |
| Groups | 80 |
| Ports | 12 inputs and 12 outputs per node |
| Label length | 120 characters (a `note` may have 400) |

The diagram source comes from a model or a user, so the page treats it as untrusted:

- **No markup is trusted.** Labels are escaped in the SVG, the data reaches the page only as JSON
  with `<`, `>` and `&` escaped, and the page sets text with `textContent`.
- **A Content-Security-Policy** allows exactly the scripts and the two stylesheets the page
  contains (the page's and the diagram's), by SHA-256, plus the pinned D3 URL (none in `inline` mode). It forbids every other request, sets
  `base-uri` and `form-action` to `'none'`, and has no inline `style` attributes. A script injected
  into the page does not run.
- **No network** beyond that one pinned script. The renderer makes no calls and runs no external
  process.
- The size limits above bound how much work a request can ask for.

## Troubleshooting

| You see | Cause and fix |
| --- | --- |
| `not valid JSON (line 3, column 5)` | The source is not JSON. Use double quotes and no trailing commas |
| `links[0].to 'x': no such node` | A link names a node that is not in `nodes` |
| `... has no output port 'y'` | Declare the port in the node's `outputs` (or `inputs`), or link without a port |
| `nodes[2].kind 'toaster': use one of ...` | The error lists the valid kinds. See [icon kinds](#icon-kinds) |
| `provider 'oracle': use one of ...` | Use a provider from the [providers](#providers) table |
| `groups[1] 'g': contains no nodes` | Every group needs at least one node, directly or in a sub-group |
| `output_format 'png' not supported for diagram type 'd3_force'` | These types render `html` and `svg` only |
| The page is blank or has no zoom | It could not load D3 from jsDelivr (offline or blocked). Set `d3_source: inline` |
| `nodes[0].logo: use a data URI such as ...` | A logo must be a `data:image/...;base64,...` URI (png, jpeg, webp or svg+xml), not a URL |
| `Saved to:` is missing and `content_base64` is large | `output_dir` was refused (outside `MCP_OUTPUT_ROOT`, or the server is read-only) |
